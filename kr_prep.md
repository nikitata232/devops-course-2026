## Ответы на вопросы:

- Когда я выберу rebase, а когда merge? Почему?
  -- Merge я выбираю, когда хочу, чтобы было видно, в какой момент ветка в которой работаю, отошла от основной ветки (main)
  Также merge в отличие от rebase абсолютно безопасен для команды, когда я использую rebase но в этой ветке работают параллельно мои люди, могут возникнуть сбои. Они просто не смогут запушить ничего. Так как у нас была одинаковая история коммитов на момент начала работы, а после моих действий совершенно разная.

- Что произойдет, если я сделаю rebase публичной ветки, в которой работают коллеги?

Для примера, пусть у нас будет одинаковая история коммитов:

-- docs -> chore -> docs

Это ветка, на которой мы все работаем, начинали с одного и того же момента. Ветка - main(основная)

Допустим, я работал на другой ветке и сделал rebase с основной веткой. Запушил еще два docs.
В итоге, ветка main сейчас выглядит так docs -> chore -> docs -> docs -> docs.
А у коллег она все ещё такая - docs -> chore -> docs
В итоге они сами не смогут запушить, возникнет конфликт. Поэтому если ты работаешь в команде, нужно использовать только merge в случае с публичными ветками, которой является main.

- Зачем нужен multi-remote и в каких реальных сценариях он применяется?

На всякий случай, например в случае сбоев на одной платформе, команда сможет работать на другой. GitHub / GitLab
